> **本文只写「要什么」**（模块 / FR / 边界 / 验收）。视觉稿与 HTML 原型**暂缓**，不阻塞需求定稿。  
> **「怎么做」** 另开里程碑（建议 W1+，或后续 `docs/Web看板路线图.md`）。  
> **基线**：`v1.60.0` ｜ 集成层 ClickUp / 练练 / DeepSeek + CLI 日流程已齐。

## 0. 一页摘要

| 问题 | 答案 |
| --- | --- |
| 要解决什么 | 在浏览器里**看清今日待办 / 已办**，并能一键从 ClickUp **刷新**；不替代 CLI 复盘主路径 |
| 怎么跑 | 本机单进程后端托管前端 `web/dist`；**随用随启、不用即停** |
| 和 CLI 关系 | **同一套业务逻辑**；Web 只是 UI + 薄 API，禁止第二套归日/拉任务实现 |
| 首期不做 | 公网、多用户、Web 内写回 ClickUp、像素主题、视觉精修 |

## 1. 定位与原则

### 1.1 产品定位

| 层 | 载体 | Web 看板扮演 |
| --- | --- | --- |
| 执行层 | ClickUp | **只读展示 + 触发拉取**（刷新） |
| 源层 | 复盘 md | 首期**不改写** md |
| 评价层 | `reviews.db` + CLI | 首期**可选只读**状态；不写库 |

Web 看板 = **本机控制台**，不是第二套生活管家，也不是 ClickUp 替代品。

### 1.2 设计原则

| ID | 原则 |
| --- | --- |
| P1 | **逻辑单源**：拉任务、归日、`LIST_*`、集成开关全部复用现有 `integrations` / `pipeline`；API 只编排 |
| P2 | **CLI 第一公民**：现有子命令行为不变；新增至多 `serve`（名可议） |
| P3 | **密钥不上前端**：Token / list 真值只在本机 `.env`；接口不回传密钥 |
| P4 | **默认可信边界**：仅 `127.0.0.1`（或等价本机回环） |
| P5 | **不破坏 G1**：刷新只读 ClickUp；不「只进库不落 md」 |
| P6 | **不改四维评分**：看板不算分、不改权重 |
| P7 | **随用随启**：无常驻系统服务要求；用户手动启停 |

### 1.3 已拍板技术约束（需求侧记下，实现遵循）

| 项 | 定调 |
| --- | --- |
| 前端 | Vite + React |
| 静态资源 | `web/dist` **提交入库**可开箱 |
| 视觉主题（方向） | 整站默认新拟物；像素以后再说（**视觉细则本阶段不做**） |
| 待办数据 | 沿用 `LIST_*` + `date_closed` 归日（含次日早上回拨） |

## 2. 用户与场景

### 2.1 用户

本人（单用户、本机）。无访客、无团队协作账号模型。

### 2.2 核心场景

| 场景 | 触发 | 期望 |
| --- | --- | --- |
| S1 晨间看今日 | 启动 serve → 打开浏览器 | 看到待办 / 已办分区；知道 ClickUp 是否可用 |
| S2 刷新同步 | 点击「刷新」 | 从 ClickUp 拉最新，两栏更新；失败有人话错误 |
| S3 对照 CLI | 同一时刻 CLI `clickup` / `clickup-done` | 口径一致，不出现「Web 一套、CLI 一套」 |
| S4 用完即走 | Ctrl+C / 关终端 | 进程退出；无后台残留要求 |

## 3. 功能模块划分

```
┌─────────────────────────────────────────────┐
│ M1 运行时外壳（serve + 静态托管 + 本机绑定）   │
├─────────────────────────────────────────────┤
│ M2 系统状态（health / mode / 集成开关只读）   │
├─────────────────────────────────────────────┤
│ M3 今日看板（待办 / 已办 / 刷新）← P0 核心   │
├─────────────────────────────────────────────┤
│ M4 导航与信息架构（侧栏多页 · P1）            │
├─────────────────────────────────────────────┤
│ M5 只读增强（doctor 灯 / 外链 · P1）         │
├─────────────────────────────────────────────┤
│ M6 写回类（改状态/评论 · P2 明确后置）        │
└─────────────────────────────────────────────┘
```

| 模块 | 职责 | 优先级 |
| --- | --- | --- |
| **M1 运行时外壳** | 启动 HTTP；挂载 `web/dist`；SPA fallback；端口可配 | P0 |
| **M2 系统状态** | 版本、LLM mode、`INTEGRATION_*` 开关摘要 | P0 |
| **M3 今日看板** | 刷新、待办列表、已办列表、加载/空/错 | P0 |
| **M4 导航 IA** | 侧栏：今日 / 待办 / 已办 /（占位）复盘·集成 | P1 |
| **M5 只读增强** | 任务 Jump to ClickUp；doctor 红绿灯只读条 | P1 |
| **M6 写回** | Web 内完成/评论（须确认语义） | P2 |

## 4. 功能需求（FR）

> 句式：**触发 → 输入 → 处理 → 输出 → 数据落点 → 验收**。

### 4.1 M1 运行时外壳

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M1-1 | 用户执行 serve 类命令后，本机浏览器可打开看板页（`dist` 已存在时） | P0 |
| FR-M1-2 | 后端同时提供 `/api/*` 与静态资源；未知前端路由回退到 `index.html` | P0 |
| FR-M1-3 | 默认监听回环地址；不默认 `0.0.0.0` | P0 |
| FR-M1-4 | `dist` 缺失时：进程给出明确修复提示（先 build），不得静默空白无说明 | P0 |

**验收**：干净机器 clone 后按文档 build（或已有 dist）→ serve → 浏览器见到壳页。

### 4.2 M2 系统状态

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M2-1 | `GET` 健康/状态接口返回：应用版本、`DAILYLUMEN_LLM_MODE`、ClickUp/练练/DeepSeek 开关布尔 | P0 |
| FR-M2-2 | 前端展示上述状态（位置：顶栏或底栏均可，实现自定） | P0 |
| FR-M2-3 | 状态接口**不得**包含 API Key、完整 list 密钥类字段 | P0 |

**验收**：改 `local/.env` 开关后刷新状态可见变化；响应体无 key 子串。

### 4.3 M3 今日看板（核心）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M3-1 | 提供「刷新」操作：从 ClickUp 拉取并重算今日待办/已办 | P0 |
| FR-M3-2 | **今日已办**：归属日为「今天」的已完成任务（规则 = 现有 `date_closed` + 次日早上回拨） | P0 |
| FR-M3-3 | **今日待办**：约定 list 范围内的未完成任务（见 §5 口径） | P0 |
| FR-M3-4 | 列表项至少含：标题、所属 list 显示名、任务 id；可选 due | P0 |
| FR-M3-5 | ClickUp 关闭 / 无凭据 / 网络失败：面板进入失败态，文案可读且无密钥 | P0 |
| FR-M3-6 | 空数据：区分「拉取成功但为空」与「尚未刷新」 | P0 |
| FR-M3-7 | 刷新过程有加载态，防止重复连点造成乱序（后发覆盖先发或禁用按钮） | P0 |

**处理约束（硬）**：实现必须调用与 CLI 共用的编排函数（可新建 `pipeline` 共享函数再让 CLI/API 同调）；禁止在 API 路由内手写归日。

**数据落点**：默认**不写** `reviews.db`、不写复盘 md；结果仅 API 响应（+ 可选本机短缓存属 P1）。

**验收**：同一配置下，Web 刷新结果与 CLI 同源函数对「今天」的拆分一致（可用 fixture 测）；开关关闭时不发网。

### 4.4 M4 导航与信息架构（P1）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M4-1 | 侧栏或等价导航：至少「今日看板」；「待办/已办」可为同页锚点或独立路由 | P1 |
| FR-M4-2 | 「复盘 / 集成」可先占位页（说明尚未实现） | P1 |

### 4.5 M5 只读增强（P1）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M5-1 | 任务可打开 ClickUp 网页链接（新标签）；Web 内不修改任务 | P1 |
| FR-M5-2 | 可选展示 doctor「收工灯」只读摘要（复用现有逻辑，不写库） | P1 |
| FR-M5-3 | 可选：按 list 分段或筛选（日常 / 习惯 / 工作） | P1 |

### 4.6 M6 写回（P2 · 默认不做）

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| FR-M6-1 | 若未来做「标完成 / 评论」：必须复用 `clickup-task` 确认语义（dry-run / 显式 apply），禁止静默写 | P2 |

## 5. 数据口径（业务单源）

### 5.1 List 范围

| List 常量 | 名称（元数据） | 首期今日看板 |
| --- | --- | --- |
| `LIST_DAILY` | 日常事务 | ✅ 纳入 |
| `LIST_HABITS` | 习惯与打卡 | ✅ 纳入 |
| `LIST_WORK` | 工作 | ✅ 纳入 |
| `LIST_INCUBATOR` | 项目孵化 | ⚪ 默认不纳入（P1 可开） |
| `LIST_ANNUAL` | 年度目标 | ⚪ 默认不纳入（P1 可开） |

> 真值 ID 仅来自 `local/.env` → Settings → `config.LIST_*`；前端只消费显示名与角色，不硬编码 ID。

### 5.2 已办归日

与现有 ClickUp 管道一致：

- 主字段：`date_closed`（东八区日历日）  
- **次日早上回拨**：命中既有规则时归属 `due_date` 日（详见 clickup-tracking skill / pipeline）  
- Web **不得**发明第二套回拨阈值  

### 5.3 待办定义（首期）

- 状态为未完成（与现 Client/管道判定一致）  
- 属于 §5.1 纳入的 list  
- 不要求 due 必须是今天（避免把「池中待办」漏掉）；若后续要「仅今天 due」作为筛选，属 P1 开关，默认关闭

## 6. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-1 | 安全 | 密钥不上前端；日志/API 错误无 token |
| NFR-2 | 绑定 | 默认 localhost；若将来支持改 bind，文档必须警告 |
| NFR-3 | 依赖 | Web 框架仅 API 层 optional；`core` 业务测试不新增第三方 |
| NFR-4 | 性能 | 单次刷新以 ClickUp 网络为准；UI 不假转无限 |
| NFR-5 | 可测 | API 层 unittest + mock；共享归日函数可单测 |
| NFR-6 | 兼容 | 现有 CLI 全量测试不得因 Web 引入而红 |
| NFR-7 | 文档 | README / 独立部署补「如何 serve / 如何 build dist」 |
| NFR-8 | 启停 | 不要求安装 Windows 服务；文档写清手动启停 |

## 7. 系统边界

### 7.1 依赖的现有能力

- `review_tool.integrations.clickup`（Client、开关）  
- ClickUp 归日 / list 元数据（`config.LIST_*`、`CLICKUP_LISTS`、pipeline 函数）  
- Settings / `INTEGRATION_CLICKUP_ENABLED`  
- （P1）doctor 收工摘要相关只读接口  

### 7.2 明确不做（首期）

| 不做 | 原因 |
| --- | --- |
| 视觉高保真定稿 / 像素主题 | 用户要求本阶段先需求、跳过原型精修 |
| 替代 WorkBuddy / DeepSeek 日流程 | 看板不负责 llm-day |
| Web 直接 ingest / 改 md | 防破坏 G1 |
| 多用户、云端部署、OAuth | 个人本机工具 |
| 再实现一套 ClickUp SDK | 防逻辑漂移 |
