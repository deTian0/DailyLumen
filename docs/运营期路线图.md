## 2. 全局约束（沿袭 M1–M21，不再重复论证）

- **md 是源、库可 100% 重建**：任何新数据仍走「先落 md（数据块 / 附录章节）→ `ingest` 入库」。
- **零依赖**：纯标准库；新增模块归入四层对应层，`tests/test_architecture.py` 强制依赖方向。
- **schema 迁移**：`PRAGMA user_version` 幂等迁移；改 CHECK 只能重建表，走用户级 skill
  `sqlite-safe-migration` 全覆盖流程；`reviews.example.db` 必须同版（测试守卫）。
- **CI 阻塞**：重建 → `doctor` / `recompute-scores` / `sync-docs --check` 全绿才可合入；
  每个里程碑**测试数净增**，README 版本头同步。
- **版本节奏**：逐 feature 单独提交 + tag，`main` fast-forward；推送后以
  `api.github.com` 核对 main 与 tag（本机 git 引用会静默丢）。
- **报告类功能只读库**，不写回 md（写回只有 `sync-docs` / `clickup-push` 两条既有通道）。

## 4. 里程碑详情

### M22 — `stats` 取数命令｜P0｜小

**背景**：2026-10-20 全套文档对账发现，过时值清一色是「随时间增长的统计值」
（复盘篇数 / 入库天数 / 打卡行数 / 库大小 / 测试数）—— 手抄必漂移，迁移指南一度
停在 v1.4.x 时代的数字上。根治方法：给文档一个取数命令。

**范围**：

- `reports/stats.py`（reports 层，只读）+ CLI `stats [--json]`，输出：
  - 复盘 md 篇数（`每日复盘/复盘/` 递归计数，按月分组明细）
  - 库内天数 / 打卡行数 / `habit_logs` 行数 / `body_metrics` / `training_sessions` 行数
  - schema 版本、库文件大小（KB）、最近入库日
  - 历史断更空洞列表（**复用 `doctor` 的既有口径**，不另写一套）
- 测试：`test_stats.py`（空库 / 有数据 / --json 三态）。

**明确不做**：不自动改任何文档（取数后人工引用，避免写循环）；不跑测试套件计数
（测试数以 CI / 全量跑为准，stats 不花十几秒跑 unittest）；不新增表。

**验收**：

- [ ] `stats` 输出与 2026-10-20 手工盘点值一致（88 篇 / 77 天 / 539 打卡 / v8 / 244 KB）
- [ ] `stats --json` 可被脚本解析，字段名稳定
- [ ] 断更列表与 `doctor` 输出一致

### M23 — 体征建议官｜P1｜中

**背景**：能力图谱 B 角色唯一 🔴：`body` 有 7 日均 / BMI / 外推周数等**分析**，
但没有一条**建议**。C 运动（coach）与 E 营养（nutrition）都证明过「确定性规则 +
每条带依据数字」的报告形态可行，体征补齐同一形态即可。

**范围**：

- `reports/body.py` 的 `render` 增「建议」段，确定性规则（同 coach 风格，每条带依据）：
  - 趋势方向：7 日均 vs 前 7 日均的斜率与方向
  - 平台期检测：近期波动 ≤ 阈值且持续 N 天
  - 距目标：复述外推 ETA（已有），方向与 `config.PROFILE` 目标比对
  - 数据不足时明确「样本不足，暂无建议」，不硬编
- 测试：规则分支全覆盖（趋势升 / 降 / 平台 / 样本不足）。

**明确不做**：不写回 md；不接 AI 生成；无新表；不引入体重秤自动导入（截图投递通道够用）。

**验收**：

- [ ] 每条建议行都带数字依据，可复算
- [ ] 无体重数据时输出说明行而非空段
- [ ] 能力图谱 B 角色「建议」🔴 → 🟢

### M24 — 周报数据要点段｜P1｜中

**背景**：W42 周总结（2026-10-20）四处叙事断言被实测推翻——「全库第三 / 近 6 周最高 /
本月第三低 / 并列非首次」，全是手算手抄的。根因：叙事手写、极值手算。
`week --write` 现在只落结构化骨架，数字部分仍是「跑命令 → 人肉抄」。

**范围**：

- `analyze.py` 的 `--write` 骨架增加「数据要点」区（全脚本计算，叙事段直接引用）：
  - 周期四维 / 系统均值 + 环比上一周期
  - 单日极值（**限定完整周口径**，不足 7 天的周自动注明——conventions §4 第 6 条）
  - 连续段（复用 streak 口径：如「system ≥ 4.00 连续 N 天」）
  - 训练日达标率（分母注明 `training_day` 来源）+ 个人打卡依从率汇总
- `--json` 同步暴露同字段。

**明确不做**：不自动写叙事正文（结论仍人下，机器只供数）；不回填旧周报 / 旧月报
（那是 conventions §4 的手工流程）；不改评分。

**验收**：

- [x] `week 42 --write --force` 产出的要点段数值与 `week 42` 输出逐项一致
      （真机 W42 实测：环比 +2.10 / 极值 2314 kcal 10-16 / 连续 9 天）
- [x] 极值断言可用 SQL 复算且口径注明「完整周」（不足 7 天自动注明「不完整周」）
- [x] W42 那四处错误断言类型，用要点段都不可能再犯（环比 / 极值 / 连续段全脚本算）

**落地注记（v1.32.0）**：`--json` 已同步暴露 `highlights`；训练日达标率与
打卡依从率汇总由既有一 / 四章承担，未在要点段重复。

### M25 — 食物明细（可选表）｜P2｜中｜✅ 完成（v1.35.0）

**背景**：需求文档 E 角色「食物明细 🔴 —— 日汇总起步，明细推迟」。现在日汇总 +

**⚠️ 前置决策点（动 schema 前必须拍板）**：每天多一道「明细录入」工序，
换来的回看价值是否真实存在。**建议先手动试运行两周**（在 md 附录手记明细，

intake skill §3.6 顺带整理截图 / 口述食物项（估算标注、不入库、不评分）；

> **裁决记录（2026-10-21）**：试记窗口**第 1 天**用户直接拍板「M25 要做」，
> 前置决策点作废 —— 不再等两周样本，按建表验收清单直接落地（v1.35.0）。
> 原「回看价值」假设未经验证，属**用户偏好优先于流程建议**的一次例外；
> 若后续实际不回看，处置方式改为「保留表但不再维护附录」，而非回滚 schema。

**范围（拍板后）**：

  schema v9 幂等迁移，走 `sqlite-safe-migration` 全覆盖流程。

**验收**：

**为什么现在做**：复盘真正的断点不在「算分」，而在**「写下的计划没人读」**。
实测 79 天里写了 129 条真实承诺（改进点 36 / 明日 Top 3 93），
`core/bodyweight.py:28` 却明说「那是计划/意愿，不是当天记录」——
代码一次都没读过。于是「复盘 → 计划 → 执行 → 对账」在最关键一环断掉。

**做法**

- [x] schema **v10** 建 `promises(date, kind, seq, text, bucket)`，`(date, kind)` 联合主键
- [x] `core/promises.py` 纯规则解析：章节定位 → 列表项抽取 → 约束抽取 → 桶分类
- [x] 滤掉两类假承诺：**模板提示语**（9 月版模板把指引写成了列表项，26 篇中招）
      与**占位符**（`空` / `忘记了` / `无`，全库 75 处）
- [x] `reports/promises.py` 次日证据型判定 + `promises` 子命令
- [x] 周报加「八、承诺兑现」段；`doctor` 加「承诺覆盖」建议性检查
- [x] 参数化约束：`60min` / `保持 5h` / `脂肪≤70g` / `23:30 前` / `≤1h` 都能抽

**口径（红线，改代码前必读）**

1. **只做证据型判定** —— 判据一律来自次日已入库的结构化字段
   （`learn_h` / `exercise_min` / `fat_g` / `bedtime` / `deepwork_h` /
   `phone_h` / `personal_tracks.done`），可复现、可单测，不猜语义
2. **判不了就说判不了** —— 映射不到字段记 `unmapped`，**不算未兑现**
3. **次日没写复盘**记 `no_data`，同样不算未兑现
4. **兑现率只在「可判定」子集上算**，分子分母都露出来
5. **不进四维评分、不加惩罚** —— 它是镜子，不是鞭子

**验收（v1.36.0 实测）**：129 条承诺 / 41 天入库；可判定 29 条，兑现率 **48%**；
`unmapped` 92 条（有话题无数字 43 + 未归类 49）在报告里显式分段说明。
802 测试全绿、ruff 干净、`doctor` 数据健康、`recompute-scores` 幂等。

**遗留（→ M30，v1.37.0 已处理）**：`work` 桶无时长约束时一律 `unmapped` ——
「migration 文件夹彻底修复」用 `deepwork_h > 0` 去核对是荒谬的（库里 92% 的天都有值）。
v1.37.0 引入 ClickUp 完成记录（`clickup_done`）作**旁证**，不改判定；
实测覆盖率只有 4/41 天 —— 本人工时记录集中在 2026-08-20 之前，与承诺窗口几乎零重叠。

### M32 — 熔断双条件：稳定低位不再报警｜P0｜小｜✅ 完成（v1.38.0）

**立项证据（2026-10-22 实测）**：79 天里 **78% 的天数至少一维处于熔断态**
（健康 48% / 学习 58% / 生活 55% / 系统 83%）；系统分 61/79 天 <6、历史最高仅
**6.5**。标尺 v2（v1.34.0 锚点插值）把全体分数下移到均值 4.0，而
`FUSE_RULES.threshold` 仍是 6（用户原始定义）—— 一个 78% 时间亮红灯的报警
等于没有报警。v1.33.2 的 `long_run_days` 降级只是补丁（要连续 14 天才降级）。

**口径（用户 2026-10-22 拍板：相对基线双条件，不是单纯降阈值）**：

- 低分判定 = 当日分 < `threshold`(6) **且** < 此前 `baseline_days`(28) 日自身
  均值 − `relative_drift`(1.0)；基线样本不足 `min_baseline_days`(7) 天不计低；
- 连续 ≥ `days`(3) 天满足双条件 → 熔断；`long_run_days` 降级逻辑保留；
- 实测熔断态天数占比 **78% → 33%**（纯降阈值到 4 只有 38%，且漏掉「突然掉下去」）。

**验收（v1.38.0 实测）**：

- [x] 真库 `fuse`：当前熔断态 2 维 → **0 维**（近 7 日全线回升被正确识别），rc=0
- [x] `test_stable_low_not_fused`（稳定低位不触发）/ `test_min_baseline_days_guard`
      / `test_baseline_adapts_after_drop`（基线适应截断连续段）三条新语义回归
- [x] 测试 845 → **848**；ruff 干净；`doctor` / `recompute-scores` 幂等
- [x] skill `dailylumen-conventions` §2 / `设计说明.md` §6 / README 版本头同步

      （历史最长连续段整体收紧：学习 20→15 / 生活 24→19）—— 下次出周报时复算。

### M33 — 采集拉齐命令（夜间一条命令）｜P1｜中

**背景**：夜间 SOP 要依次跑 `keepstrong --write` → `habits --sync` → `ingest`
三条命令、记三组参数（见 skill `daily-review-intake`），任何一步忘跑就静默缺数
—— `body_metrics` 78 天 0 行、`habit_logs` 只有 5 行的根因不是「没数据」，
是「链路没触发」。采集面不再扩张（运营期约束），但**摩擦必须降**。

**范围**：

- 新增 CLI 子命令（名字立项时定，`daily-pull` 为占位）：一条命令完成
  练练素材拉取落 md（`--write` 语义）→ 习惯快照同步（`habits --sync` 语义）
  → `ingest` 全量入库 → 收尾汇报（当天各表新增行数 + doctor 新鲜度一行）。
- **只允许夜间使用**（打网：练练 + ClickUp）；晨间不打网纪律不变。
  命令默认 dry-run 打印将执行的动作，`--apply` 才真跑（沿袭 `clickup-push` 惯例）。
- 各步骤沿用既有模块（pipeline / storage），新命令只做**编排**，不重算。

**明确不做**：不做定时任务（v1.4.6 已废除调度的决定不变）；不自动写叙事；
失败步骤显式报错并继续跑其余步骤（退出码取最差）。

**验收**：

- [ ] dry-run 不打网、不写库，打印计划动作
- [ ] `--apply` 后当天 md 数据块 / `habit_logs` / `daily_reviews` 同步就位
- [ ] 练练 401（Key 过期）时命令**不静默**：显式提示换 Key（conventions §6）
