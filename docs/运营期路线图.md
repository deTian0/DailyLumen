## 2. 全局约束（沿袭 M1–M21，不再重复论证）

- **md 是源、库可 100% 重建**：任何新数据仍走「先落 md（数据块 / 附录章节）→ `ingest` 入库」。
- **零依赖**：纯标准库；新增模块归入四层对应层，`tests/test_architecture.py` 强制依赖方向。
- **schema 迁移**：`PRAGMA user_version` 幂等迁移；改 CHECK 只能重建表，走用户级 skill
  `sqlite-safe-migration` 全覆盖流程；`reviews.example.db` 必须同版（测试守卫）。
- **CI 阻塞**：重建 → `doctor` / `recompute-scores` / `sync-docs --check` 全绿才可合入；
  每个里程碑**测试数净增**，README 版本头同步。
- **版本节奏**：逐 feature 单独提交 + tag，`main` fast-forward；推送后以
  `api.github.com` 核对 main 与 tag（本机 git 引用会静默丢）。
- **报告类功能只读库**，不写回 md（写回只有 `sync-docs` / `clickup-push` 两条既有通道）。

## 4. 里程碑详情

### M22 — `stats` 取数命令｜P0｜小

**背景**：2026-10-20 全套文档对账发现，过时值清一色是「随时间增长的统计值」
（复盘篇数 / 入库天数 / 打卡行数 / 库大小 / 测试数）—— 手抄必漂移，迁移指南一度
停在 v1.4.x 时代的数字上。根治方法：给文档一个取数命令。

**范围**：

- `reports/stats.py`（reports 层，只读）+ CLI `stats [--json]`，输出：
  - 复盘 md 篇数（`每日复盘/复盘/` 递归计数，按月分组明细）
  - 库内天数 / 打卡行数 / `habit_logs` 行数 / `body_metrics` / `training_sessions` 行数
  - schema 版本、库文件大小（KB）、最近入库日
  - 历史断更空洞列表（**复用 `doctor` 的既有口径**，不另写一套）
- 测试：`test_stats.py`（空库 / 有数据 / --json 三态）。

**明确不做**：不自动改任何文档（取数后人工引用，避免写循环）；不跑测试套件计数
（测试数以 CI / 全量跑为准，stats 不花十几秒跑 unittest）；不新增表。

**验收**：

- [ ] `stats` 输出与 2026-10-20 手工盘点值一致（88 篇 / 77 天 / 539 打卡 / v8 / 244 KB）
- [ ] `stats --json` 可被脚本解析，字段名稳定
- [ ] 断更列表与 `doctor` 输出一致

### M23 — 体征建议官｜P1｜中

**背景**：能力图谱 B 角色唯一 🔴：`body` 有 7 日均 / BMI / 外推周数等**分析**，
但没有一条**建议**。C 运动（coach）与 E 营养（nutrition）都证明过「确定性规则 +
每条带依据数字」的报告形态可行，体征补齐同一形态即可。

**范围**：

- `reports/body.py` 的 `render` 增「建议」段，确定性规则（同 coach 风格，每条带依据）：
  - 趋势方向：7 日均 vs 前 7 日均的斜率与方向
  - 平台期检测：近期波动 ≤ 阈值且持续 N 天
  - 距目标：复述外推 ETA（已有），方向与 `config.PROFILE` 目标比对
  - 数据不足时明确「样本不足，暂无建议」，不硬编
- 测试：规则分支全覆盖（趋势升 / 降 / 平台 / 样本不足）。

**明确不做**：不写回 md；不接 AI 生成；无新表；不引入体重秤自动导入（截图投递通道够用）。

**验收**：

- [ ] 每条建议行都带数字依据，可复算
- [ ] 无体重数据时输出说明行而非空段
- [ ] 能力图谱 B 角色「建议」🔴 → 🟢

### M24 — 周报数据要点段｜P1｜中

**背景**：W42 周总结（2026-10-20）四处叙事断言被实测推翻——「全库第三 / 近 6 周最高 /
本月第三低 / 并列非首次」，全是手算手抄的。根因：叙事手写、极值手算。
`week --write` 现在只落结构化骨架，数字部分仍是「跑命令 → 人肉抄」。

**范围**：

- `analyze.py` 的 `--write` 骨架增加「数据要点」区（全脚本计算，叙事段直接引用）：
  - 周期四维 / 系统均值 + 环比上一周期
  - 单日极值（**限定完整周口径**，不足 7 天的周自动注明——conventions §4 第 6 条）
  - 连续段（复用 streak 口径：如「system ≥ 4.00 连续 N 天」）
  - 训练日达标率（分母注明 `training_day` 来源）+ 个人打卡依从率汇总
- `--json` 同步暴露同字段。

**明确不做**：不自动写叙事正文（结论仍人下，机器只供数）；不回填旧周报 / 旧月报
（那是 conventions §4 的手工流程）；不改评分。

**验收**：

- [x] `week 42 --write --force` 产出的要点段数值与 `week 42` 输出逐项一致
      （真机 W42 实测：环比 +2.10 / 极值 2314 kcal 10-16 / 连续 9 天）
- [x] 极值断言可用 SQL 复算且口径注明「完整周」（不足 7 天自动注明「不完整周」）
- [x] W42 那四处错误断言类型，用要点段都不可能再犯（环比 / 极值 / 连续段全脚本算）

**落地注记（v1.32.0）**：`--json` 已同步暴露 `highlights`；训练日达标率与
打卡依从率汇总由既有一 / 四章承担，未在要点段重复。

### M25 — 食物明细（可选表）｜P2｜中

**背景**：需求文档 E 角色「食物明细 🔴 —— 日汇总起步，明细推迟」。现在日汇总 +
FOOD_LIB 建议已稳定运行，缺的只是「回看某天吃了什么」。

**⚠️ 前置决策点（动 schema 前必须拍板）**：每天多一道「明细录入」工序，
换来的回看价值是否真实存在。**建议先手动试运行两周**（在 md 附录手记明细，
不建表），确认真的会回看、真的会引用，再动 schema —— 避免为「看起来该有」的表付费。

**范围（拍板后）**：

- 表 `nutrition_items`（date / meal / desc / kcal / protein_g / carb_g / fat_g），
  schema v9 幂等迁移，走 `sqlite-safe-migration` 全覆盖流程。
- 数据通道守 G1：截图 → AI 读 → md 附录「食物明细」→ `ingest` 解析入库。
- `nutrition` 报告增加当日明细下钻段。

**明确不做**：不做自动图像识别入库；明细**不参与评分**（延续 R 系列边界）；
不做 kcal 精确化（估算值标注估算）。

**验收**：

- [ ] 迁移幂等；从 md 重建含明细且逐字段一致
- [ ] `reviews.example.db` 同步 v9
- [ ] `nutrition --date` 能下钻到当日明细

### M26 — 口述流水结构化｜P2｜小

**背景**：能力图谱 A 角色建议 🟡「口述 → 结构化流水：无字段级结构」。素材投递已定版
「睡前一次性」（§0.5），口述流水是它的低摩擦补充——躺床上不想打字时的出口。

**范围**：

- skill `daily-review-intake` 新增 §0.6「口述流水」：口述文本 → 固定字段草稿
  （三件事 / 改进点 / 明日 Top3 候选）→ 落 `收件箱/` 素材稿 → 人工确认后回填 md。
- 纯 skill 层，**零代码、零 schema**。

**明确不做**：不做语音转写工程；三条不许（不缺项不出稿 / 不估算 / 不把「没提」当「做了」）原样沿用。

**验收**：

- [x] 一条口述消息产出结构化草稿，无编造字段（§0.6：四块固定字段，未提写「（未提）」）
- [x] 草稿格式与收件箱既有素材约定一致（落 `收件箱/口述流水-<日期>.md`，不参与 ingest）

### M27 — 月度深评一键聚合｜P2｜中

**背景**：月报 `month --write` 只有结构化骨架；`chart` / `correlate` / `fuse` / `stats`
各自为战，做一次月度回顾要在四五条命令间来回抄。

**范围**：

- `reports/monthly.py` + CLI `month <YYYYMM> --deep`：聚合输出一份「深评素材 md」——
  month 结构化数据 + 本月图表（chart 落 SVG 引用）+ 月窗口 correlate + fuse 信号 +
  stats 快照。全部数字可溯源到既有命令输出。
- 排最后的原因：它依赖 M22（stats）与 M24（要点段口径），是整合层。

**明确不做**：不写叙事结论；不出 HTML（零依赖约束下渲染不可控，md + SVG 够用）；
不改评分与熔断口径。

**验收**：

- [ ] `month 202610 --deep` 产出素材 md，每个数字都能用对应单命令复现
- [ ] 图表文件落 `exports/charts/`（或既有 chart 输出目录），md 内相对引用
