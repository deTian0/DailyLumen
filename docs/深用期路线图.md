## 2. 全局约束（沿袭前三代，不再重复论证）

- **md 是源、库可 100% 重建**：任何新数据仍走「先落 md（数据块 / 附录章节）→ `ingest` 入库」。
- **零依赖**：纯标准库；新增模块归入四层对应层，`tests/test_architecture.py` 强制依赖方向。
- **schema 迁移**：`PRAGMA user_version` 幂等迁移；改 CHECK 只能重建表，走用户级 skill
  `sqlite-safe-migration` 全覆盖流程；`reviews.example.db` 必须同版（测试守卫）。
- **CI 阻塞**：重建 → `doctor` / `recompute-scores` / `sync-docs --check` 全绿才可合入；
  每个里程碑**测试数净增**，README 版本头同步。
- **版本节奏**：逐 feature 单独提交 + tag，`main` fast-forward；推送后以
  `api.github.com` 核对 main 与 tag（本机 git 引用会静默丢）。
- **报告类功能只读库**，不写回 md（写回只有 `sync-docs` / `clickup-push` 两条既有通道）。
- **候选草稿不入库**：收件箱候选 md 不参与 `ingest`（沿袭 M34）。
- **独立指标不进四维**：体重 / 习惯 / 训练告警挂独立段，**不改** `fuse` 的 rc=1 语义、
  不改四维权重、不动历史分。

### M36 — 今日三件事候选（FR-A3）｜P0｜中｜目标 v1.43.0

**背景**：承诺写侧已有 M34 `promise-draft`（明日 Top 3 候选），但复盘「二、今日三件事」
仍常空 —— 用户要回想「今天做成了什么」。ClickUp **当日已完成**任务天然是候选池，
与 `promise-draft` 对称：一个面向「明日要做」，一个面向「今日做成」。

**范围（文件级）**：

- 新增 `review_tool/pipeline/three_things_draft.py`（或等价命名），**镜像**
  `review_tool/pipeline/promise_draft.py`：
  - 候选池 = **当日已完成** ClickUp 任务（复用 `pipeline/clickup.py` / list 映射，
    skill `clickup-tracking` 口径）
  - 按「有产出」启发式排序（标题含交付物 / 时长数字优先；无则按关闭时间）
  - 落 `每日复盘/收件箱/三件事候选-<日期>.md`；**不入库**；人勾 ≤3 回填「二、今日三件事」
- CLI：`python -m review_tool three-things-draft [--date D] [--stdout] [--out DIR]`
  （命令名可微调，以 ROUTES 注册为准）
- skill `daily-review-intake`：补「勾选回填今日三件事」步骤（对称 §0.7 明日候选）
- 测试：空候选 / 有完成项 / 草稿不进 ingest / 与 `promise-draft` 文件名互不覆盖

**明确不做**：

- 不自动回填复盘正文；机器只搬运不编造
- 不与 `promise-draft` 混用同一草稿文件
- 不改 `promises` / `clickup_done` schema；不改四维评分

**验收**：

- [x] 一条命令产出 `收件箱/三件事候选-<日期>.md`，条目来自当日已完成真实任务
- [x] 未勾选前复盘 md / 库无新增三件事行
- [x] 与 `promise-draft` 物理分文件；同日可并存
- [x] intake skill 有勾选回填步骤；测试净增
