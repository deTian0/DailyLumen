### F1 — FR-E4 三餐结构评分｜P0｜目标 v1.106.0 ⬜

**目标**：兑现需求文档 FR-E4 —— 在独立指标区给出**确定性**三餐结构评价：早餐按时 / 加餐次数 / 晚间热量占比；升级现有粗颗粒 `meal_structure()`，**不进四维**。

**实现要点**

1. **`config.NUTRITION_RULES` 增键**（默认值可调，写进设计说明）：
   - `snack_soft_max`（默认 2）：加餐次数软上限
   - `evening_kcal_share_soft`（默认 0.40）：晚餐（± 规则内加餐）占当日明细 kcal 的软上限
   - `structure_weights`：breakfast / snack / evening 三项权重（和为 1）
2. **`core.nutrition.meal_structure` 升级**（保持旧键兼容）：
   - 入参增加可选 `items: list[dict]`（已是 meal/kcal 形态；由 reports 传入，core 零 I/O）
   - 新增输出：`snack_count`、`evening_kcal`、`day_kcal_from_items`、`evening_share`、`structure_score`（0–100 或 `None`）、`structure_band`（如 优/中/弱）、`structure_notes`
   - **计算口径**：
     - 早餐按时：仍读 `breakfast_on_time`（1/0/None）
     - 加餐次数：`items` 中 `meal=="snack"` 条数；无 items → `None`（降级不罚分项）
     - 晚间占比：`dinner` kcal 合计 / 明细总 kcal；若规则将「夜宵」已归一进 `snack`，**默认晚餐-only**；可在 notes 提示「含加餐则另计」——**不要**把 snack 默认并进晚间，除非配置显式 `evening_includes_snack=True`
     - 无明细或总 kcal 不可得 → `evening_share=None`，结构分只用有值的子项按权重重归一；三子项全无 → `structure_score=None`
   - 旧字段 `meals_count` / `notes` / `suggest_slot` **保留**；`suggest_slot` 可参考新 notes，但语义不变（启发式补哪一餐）
3. **`reports/nutrition.collect/render`**：把 items 传入 `meal_structure`；文本段「三餐结构」展示新字段；JSON 同步
4. **可选挂周报**：`reports/analyze` 营养相关段若已引用 `meal_structure`，改为展示 `structure_score` 周均（有值日）；**无则本项可只做 nutrition 命令，周报挂接声明为 F1 内可选**
5. **测试**：纯函数测 —— 有明细 / 无明细 / 仅早餐字段 / 晚间超标 / 加餐超标 / 权重重归一；nutrition 报告单测快照级断言关键行；`test_core_is_io_free` 保持绿
6. **Web**：本里程碑**不强制**新 UI；若已有 Life/Analytics 营养只读出口，R1 自动吃到新 JSON 字段即可。禁止前端重算结构分。

**验收**

- [ ] `meal_structure` 在无 items 时行为与升级前兼容（旧键仍在；新键为 None / 降级）
- [ ] 有 items 时 snack_count / evening_share / structure_score 可手工复算
- [ ] 结构分不参与四维；全量测试 + ruff 绿；四处版本 v1.106.0；设计说明变更日志一条；不打 tag

**明确不做**：改 `diet_kcal` 评分；强制人人填明细；schema 新列；Web 专门新页。

### F2 — FR-F5 轻量学习周报｜P1｜目标 v1.107.0 ⬜

**目标**：在已有 `tutor`「本周主题 / 投入 / 产出物」上补齐 FR-F5 缺口 —— **`learn_h` 投入兜底** + **书单/课表旁证**；明细仍薄时周报可读，不新建子命令。

**实现要点**

1. **`core.learning`**：新增纯函数，例如 `hours_fallback(learn_h_by_day: list) -> dict`（总小时 / 有值天数 / 日均）；`week_rollup` 保持只吃 `learning_logs`，**不**在 core 读库
2. **`reports/tutor.collect`**：
   - 额外查锚点周内 `daily_reviews.learn_h`（reports 层 SQL）
   - `week` 对象增加：`learn_h_total` / `learn_h_days` / `logs_minutes`（原 rollup）/ `hours_source`（`logs` | `learn_h` | `mixed` | `none`）
   - 展示规则：有 `learning_logs` 分钟 → 主展示 logs；logs 空但 learn_h 有值 → 文案标明「来自日汇总 learn_h（附录学习记录为空）」；二者皆有 → mixed，并排不双计总分（避免 45min 日志 + 0.75h 汇总加两次）—— **默认以 logs 为准，learn_h 仅补空日**
3. **书单旁证（只读、可关）**：
   - 复用 `LEARNING_LIST_IDS` / ClickUp 只读拉「未完成或近期完成任务标题」作旁证列表（最多 N 条）
   - 失败映射与既有集成一致（无凭据 / 429 / 不可达 → 段内提示，不炸命令）
   - **不做**进度百分比、不落库、不改 ClickUp
4. **`week_section_lines` / `render`**：输出补「投入（learn_h 兜底说明）」与「书单旁证」小节；analyze 周报挂段若调用 `week_section_lines`，自动受益
5. **测试**：rollup 与 fallback 纯函数；tutor collect 用临时库；ClickUp 旁证全 mock；无凭据时仍 0 退出

**验收**

- [ ] `learning_logs` 空 + 有 `learn_h` → 周报仍有投入行且标明来源
- [ ] logs 与 learn_h 同日并存不双计
- [ ] 书单旁证失败不导致 tutor 非 0（除非其它硬错）
- [ ] 全量测试 + ruff 绿；四处版本 v1.107.0；设计说明一条；不打 tag

**明确不做**：新表；SM-2 改间隔；Web 新「学习」向导；讲解/出题落库；强制回填 learning_logs。
