### E1 — FR-K3 drafts Web（候选草稿预览→收件箱）｜P0｜目标 v1.100.0 ✅

**目标**：PRD FR-K3 收口 —— promise / three-things / improve 三个候选草稿在 Web 上「预览 → 确认落收件箱 md」，复用 `plan→confirm` 注册表；**不做** Web 端勾选回填。

**实现要点**

- 后端：`api/writes/drafts.py` 三个动作（`promise_draft` / `three_things_draft` / `improve_draft`）
  - plan：复用 `pipeline.promise_draft.candidate_pool + build_draft`、`pipeline.three_things_draft` 同款、
    `reports.improve_draft.build_skeleton`（ai-context 同源 `build_context`，须传只读 `conn`）——
    **内存渲染，零写盘**；preview 给候选条目数组 + 将落文件名
  - confirm：把预览时冻结的 md 文本写入 `收件箱/<前缀>-<日期>.md`（防穿越：文件名由服务端拼，不收用户路径）；
    已存在时 plan 预览里标注「将覆盖」，confirm 前备份旧文件到临时目录不保留（或拒绝覆盖——以 plan 文案为准，**拒绝覆盖**更稳：已存在 → 422 `draft_exists`，提示用 CLI `--out` 或先归档）
  - promise / three-things 需 `env`（ClickUp 凭据，可注入 `fetch`）；improve 需只读 `db_path`
  - 错误映射对齐 B15：401/403→`upstream_auth`、429→`rate_limited`、URLError→`upstream_unreachable`
- 前端：Life 新 tab「候选草稿」（`Drafts.jsx`）三卡；improve 卡只读展示取数上下文（Markdown）+ 说明「排序查书仍须走 life-decision-guide 会话」；确认后提示「已落收件箱，去复盘 md 勾选回填」
- 红线：草稿**不入库**（文件名带「候选」前缀，ingest 本就跳过收件箱）；机器只搬运不编造（候选 = ClickUp 任务名原样 / ai-context 同源数字）

**验收**

- [x] 三个动作 plan 零写盘（内存渲染，注册表可见）；confirm 后收件箱出现草稿 md（临时目录测试）
- [x] 已存在同名草稿 → 422 `draft_exists`，不静默覆盖
- [x] ClickUp 失败映射 401/429/URLError；improve 无库 → 503 `db_missing`
- [x] 注册表与 422 / 门禁覆盖；前端 Vitest；`--enable-write` + key 门禁一致
- [x] 全量 Python + 前端测试绿；ruff 全绿；四处版本 v1.100.0；不打 tag

**明确不做**：Web 勾选回填；改候选池口径；improve 自动查书排序。
