## 3. 里程碑详情

### M1 — ClickUp 回写通道（双向同步）｜最高优先

**目标**：建立一条**受控的、单向权威的**写回通道 —— 当某天的复盘已入库时，把 ClickUp
「习惯与打卡」里的**每日复盘总结**元任务标记为完成，让 ClickUp 侧反映"复盘已完成"。

**为什么（证据）**：ClickUp「习惯与打卡」list（`901422213139`）含一条长期任务「每日复盘总结」；
目前数据只从 ClickUp **下来**（素材），没有上去 —— 你每天在 ClickUp 里还得手工勾它。

**范围**

- 新增 `review_tool/pipeline/clickup_sync.py`（**归 pipeline 层**，`import` 只允许 `core` / 自身）。
- CLI：`python -m review_tool clickup-push [YYYY-MM-DD] [--apply] [--dry-run] [--list ID]`
  - **默认 `--dry-run`**（只打印将要做什么，**不写**）；只有显式 `--apply` 才真写。
- 写入条件（**必须全部满足**）：
  1. 目标日在 `daily_reviews` 里**已存在**（复盘确实入库了）；
  2. 能唯一定位到「每日复盘总结」任务（按 `config` 里写死的 `CLICKUP_REVIEW_TASK` 名字 / id 匹配）；
  3. 该任务当前**不是** `complete`（幂等：已完成则跳过，不重复写）。
- 写入动作：`PUT /task/{id}` 置为完成 → **随后 `GET` 回读**校验 `status.type == "closed"` /
  `date_closed` 非空；回读不符则重试一次，仍失败则报错退出（**不信状态码**，ClickUp 有"200 但静默忽略"的已知行为）。

**🔴 冲突规则（先定死，写进 skill 与文档）**

| 规则 | 内容 |
| --- | --- |
| 权威方向 | **复盘（库）为权威 → ClickUp 为下游**。**永远不由 ClickUp 反推复盘**。 |
| 写谁 | **只写本系统负责的元任务**（每日复盘总结）。**绝不碰**用户手工建的任务 / 用户手动改过的状态。 |
| 幂等 | 已 complete 跳过；**不用**"先清空再写"。 |
| 默认安全 | 默认 `--dry-run`；`--apply` 是显式动作。 |
| 失败保守 | 回读不符即失败退出，**不做乐观假设**、不写第二遍以外的东西。 |

**涉及文件**

- 新增 `review_tool/pipeline/clickup_sync.py`
- 改 `review_tool/__main__.py`（`ROUTES` + docstring 用法 + import）
- 改 `review_tool/config.py`（`CLICKUP_REVIEW_TASK` 定位信息；`FEATURES` 里**可选**加 `clickup_push: False` 开关）
- 新增 `tests/test_clickup_sync.py`
- 文档：`docs/设计说明.md`（ClickUp 章节 + 变更日志）、`README.md` / `review_tool/README.md`（CLI 表、测试数）
- skill：`clickup-tracking` §3「唯一允许的写方向」**升级为正式命令**并补冲突规则

**验收**

- [ ] 单测（**全部离线**，注入假 `fetch` / 假 `put`）：dry-run 不写 / 幂等跳过 / 已入库才写 / 回读校验失败即报错 / 缺凭据报错（退出码 2）
- [ ] 真机 `--dry-run` 对某入库日跑通（只打印）；`--apply` 后 `GET` 回读为 completed
- [ ] `python -m unittest discover -s tests -t .` 全绿；`ruff` 干净
- [ ] 版本四处对齐 **v1.7.0**；commit + tag

**边界 / 风险**

- 这是系统**首次主动写外部服务** —— 必须把"默认 dry-run + 回读校验 + 幂等"三条钉在代码与测试里。
- token 是 **pk_ 全权**（ClickUp 个人 token 无 scope 限制）→ 写权限等同整库。skill §7 已警示；本里程碑不改此现状。

### M2 — ClickUp 素材源增强｜高（ClickUp 第二项，**可选**）

**目标**：素材简报不止「今天完成了什么」，补齐**判断明日该做什么**需要的信息。

**为什么（证据）**：`render()` 现只有「当日完成」「当日到期未完成」两段（`pipeline/clickup.py:221`）；
`select_completed` / `select_due_open` 各一个。缺"进行中 / 逾期 / 跨天挂着"的视角 → 喂不了「明日 Top 3」。

**范围**

- `clickup.py` 增加选取函数：`select_in_progress`（未关闭且在推进）、`select_overdue`
  （`due_date` 已过且未关闭）、**跨天未闭合**（`date_created` 早于目标日、仍未闭合）。
- `render()` 增加对应段落；**跨天未闭合**给明确提示（"挂了 N 天"，避免堆积不可见）。
- 可选：`config.CLICKUP_LISTS` 纳入「工作」「成长课」「阅读与学习」，并在渲染时按来源分组。
- 口径不变：**仍然只读**、不落库、不参与评分；已完成的归日仍看 `date_closed`。

**验收**

- [ ] 单测覆盖新选取函数与渲染段落（离线）
- [ ] 真机 `--stdout` 样例正确（含跨天未闭合提示）
- [ ] 文档 + skill 同步；版本 **v1.7.1**；commit + tag

### M3 — 周总结落盘自动化（`week --write`）｜高

**目标**：把周报从"手抄"变成"命令产出"：`week --write` 落
`每日复盘/复盘/YYYY-MM/周总结-W{ISO}-{起}_{止}.md`，格式与现有 7 份**一致**。

**为什么（证据）**：`复盘/*/周总结-W*.md` 已有 **7 份**，头部写明"由 DailyLumen 周分析脚本
（`python -m review_tool week 41`）生成"，但 `analyze.py` **没有任何写文件逻辑** ——
7 份全是手写，命名与章节口径已经在漂。

**范围**

- `reports/analyze.py` 增加 **md 渲染器**（对齐现有章节：`一、四维总览` … / 口径提示行 / 数据完整度行）。
- `week` / `month` 增加 flag：`--write`（落文件）、`--force`（覆盖）、`--check`（只比对不写，供 CI）。
- 落点目录推导**复用** `config` 现有方式（`__file__` 推导），**不要写绝对路径**。
- 幂等：已存在默认**不覆盖**，需 `--force`。

**先做的一步（关键）**：拿 W38–W41（现行口径）**先重生成再逐字 diff** 现有文件 ——
渲染器要**迁就现有格式**，而不是反过来让历史文件迁就新渲染器。diff 出来的差异逐条判断：
是"手写笔误"还是"格式缺项"。

**验收**

- [ ] 对 W38–W41 重生成，与现有文件 diff 差异**可逐条解释**（写入计划：是否回填历史由用户定）

- [ ] `--check` 模式在 CI 可用；文档 + skill 同步；版本 **v1.8.0**；commit + tag

**🔴 决策点**：现有 7 份是否用新渲染器**回填统一**？（默认：先不回填，只保证"新的一周开始自动落盘"。）

### M5 — 历史断更清单（`doctor` 增强）｜高

**目标**：`doctor` 报出**历史空洞**（相邻入库日间隔 > 1 天），不只报"最新距今几天"。

**为什么（证据）**：实测 **4 处断更**，最大 `2026-08-05 → 08-17` **缺 11 天**；
现在 `doctor` 只输出 `stale_days`（最新距今），这些空洞**完全无声**。

**范围**

- `reports/doctor.py` 增加「断更」段：逐处列出 `起 → 止 / 缺失天数`，并汇总（共 N 处 / 共缺 M 天）。
- 与现有 `[打卡对账]` / `[分数漂移]` 同级输出；**不改判定逻辑**，只增可见性。

**验收**

- [ ] 单测（构造带空洞的库，断言断更处数与天数）
- [ ] 真机 `doctor` 输出与实测 4 处一致
