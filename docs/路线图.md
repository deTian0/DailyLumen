## 0. 怎么用这份文档（给执行者 / WorkBuddy）

1. **开工前先加载 skill**（禁止凭直觉定口径）：
   - 必读：项目级 `dailylumen-conventions`（范围边界 / 权威归属 / 评分与熔断 / 工程约定 / 交付流程）

     `safe-write`（每次写盘后回读校验）
2. **一次只做一个里程碑**：一个里程碑 = 一个 feature = **一处版本号 + 一个 commit + 一个 tag**。
   不要跨里程碑混提交，也不要顺手把别的里程碑一起做。
3. **每个里程碑的验收清单必须逐条勾掉**才算完成（见 §4 DoD）。
4. **决策点**：文里标了 🔴 的地方需要用户拍板，**攒起来一次性问**，不要边做边问。
5. 完成后：在 §1 总览表把「状态」改为 ✅ 并填版本；在 `docs/设计说明.md` 变更日志加条目；
   追加 `.workbuddy/memory/YYYY-MM-DD.md`。

**doctor 控台（新增证据）**

- 默认 Windows GBK 码页下，`python -m review_tool doctor` 会在打印含 `✓` 的行时
  `UnicodeEncodeError: 'gbk' codec can't encode character '\u2713'`。
- 设 `PYTHONIOENCODING=utf-8` 可绕过；**正确修法**是渲染层对非 UTF-8 stdout 降级为 ASCII 标记
  （并入 **M2**，与断更清单同属 doctor 产出层）。

**ClickUp（下行 v1.6.0；回写 v1.7.0 / M1 ✅）**

- 只读：`python -m review_tool clickup [YYYY-MM-DD] [--out DIR] [--stdout] [--list ID]`。
- 回写：`python -m review_tool clickup-push [YYYY-MM-DD] [--apply]`（默认 dry-run）。
- 现有渲染：① 当日完成 ② 当日到期未完成（参考）—— 仅 `select_completed` / `select_due_open`。
- 边界写死：不落库 / 不参与评分 / 归日看 `date_closed`（含 v1.12.0「次日早上补勾」回拨）/ 两套打卡不许混；回写只碰元任务。
- **仍缺**：进行中 / 逾期 / 跨天未闭合（**M5**，可选）。

**外部阻塞（不进里程碑）**

- 本地 `main` **ahead origin/main 36**（含 v1.5.1…v1.7.0 等）；公司内网 DNS 解析不了
  `github.com`。**用户决定暂不处理**；网络恢复后一次性 `git push origin main --tags`。
  **不要为它再花时间造缓解方案；本任务禁止 push/pull/reset。**

## 4. 执行约定（每个里程碑都适用 · DoD）

一个里程碑**只有全部满足**才算完成：

- [ ] **测试**：新增用例（**全部离线**）；`python -m unittest discover -s tests -t .` **全绿**；
      测试总数在 README / `review_tool/README.md` 同步更新。
- [ ] **Lint**：`ruff check .` 干净（本机 ruff 在 `envs/default/Scripts/ruff.exe`）。
- [ ] **架构守卫**：`tests/test_architecture.py` 通过（新模块归对层、依赖方向正确）。
- [ ] **版本四处对齐**：`pyproject.toml` / `review_tool/__init__.py` / `README.md` 头 / `docs/设计说明.md` 变更日志。
- [ ] **文档**：`docs/设计说明.md` 加变更日志条目（口径变化必写清）；必要时加设计要点。
- [ ] **README**：`README.md`（CLI 表 / 模块地图 / 测试数）+ `review_tool/README.md` 同步。
- [ ] **skill**：受影响的项目级 skill 同步。
- [ ] **写盘回读**：每次写文件后**回读校验**（哈希 / 子串断言），不信工具的成功回报。
- [ ] **提交**：`git add -A` → 语义化 commit → `git tag -a vX.Y.Z`；工作树必须干净。
- [ ] **记忆**：追加 `.workbuddy/memory/YYYY-MM-DD.md`。

**给执行者的一句话模板**：

> 按 `docs/路线图.md` 的 **M{编号}** 开发：先加载 `dailylumen-conventions`（+ 该项标注的 skill），
> 严格照 §3 的范围与验收清单做，走 §4 的 DoD，一次只做这一个里程碑。
