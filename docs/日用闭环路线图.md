# DailyLumen · 日用闭环路线图（D1–D7）

> **用途**：给 Cursor / Claude 的**现行**开发计划书（日用闭环阶段）。
> **阶段一句话**：把「今晚 / 训练日 / 一日三步」从 CLI 拼装收成 Web 可点、可见状态的短闭环；**数据变厚只是副作用**。
> **前置**：Web 看板 W0–W18 ✅ + B2–B19 ✅（代码基线 **v1.92.0**）；B12 用户跳过；B13 / B20–B22 不做或不在本阶段。
> **权威指针**：现状 → [`能力图谱.md`](能力图谱.md)；Web 历史与 B 项收口 → [`Web看板路线图.md`](Web看板路线图.md)。
> **排序原则**：**先打通可点的写 md / 状态可见 → 再补导流条与鲜度提示 → 最后薄封装夜间拉齐与文案分支**。
> **开阶段日期**：2026-11-12。

## 2. 全局口径（本阶段全部适用）

### 2.1 继承红线（违反即返工）

| # | 口径 |
| --- | --- |
| **G1** | 练练数据是输入通道：先落 **复盘 md**，再 `ingest`；禁止只写库不落 md |
| **G2** | 不改四维评分权重 / 历史分 |
| **R1** | 单源：训练日状态复用 `keepstrong_completed_hint` / 既有查询；前端不另算口径 |
| **R2** | `exercise_min` 仍是健康分唯一运动输入；只经 md→ingest 派生 |
| **R3** | `habit_logs` ≠ `personal_tracks`；`clickup_habit` **只写 ClickUp**，不写 `habit_logs` / `training_*` |

### 2.2 本阶段新增纪律

- 🔴 **禁止静默自动勾** ClickUp「练练健身」；代勾必须 plan→confirm（沿用 B15）。
- 🔴 **`ks_*` ≠ md sync**：W17/B4 的六动作是练练 **App 写回**（不落库）；D1 的 `keepstrong_sync` 是 **写复盘 md**。路由名 / UI 文案必须带 `sync` 或「写入复盘」，不得塞进现有 `ks_*`。
- 🔴 **`ReviewSteps` 四步是复盘路径**；训练日状态条 **并列**，禁止把训练步骤塞进四步冒充复盘进度。
- 🔴 不与 Web **B 项**混在同一 commit；本阶段主清单是 D*，不是 B23+。

### 2.3 整阶段明确不做

- 多步「不可拆 token」训练超级向导
- FR-K3 三类 draft（promise / three-things / improve）上 Web
- B12 批量改期 / 改状态；B13 缩略图缩放；B20–B22 阅读/视觉回归/跟随系统
- 主题 / token 再调（B19 已冻结）；补打 tag；项目内定时调度

## 3. 里程碑详情

### D1 — Web `keepstrong_sync`（落 md ± ingest）｜P0｜目标 v1.93.0

**目标**：在面板上用 plan→confirm 把练练当日 `completed` 写入复盘 md（复用 CLI `keepstrong --write`），可选引导下一步 ingest；**不是**练练 App 写回。

**为什么第一**：没有落 md，训练日闭环与行数加厚都无从谈起；CLI 已通，缺 Web 动作。

**实现要点**

- 后端：新写动作（建议 `keepstrong_sync` / `ks_write_md` 类名，**禁止**复用 `ks_set_weight` 等）；`plan_*` 预览路径与将改字段；`confirm` 调 `pipeline.keepstrong_sync.write_sync`；写后回读 md
- 可选「下一步 ingest」：复用既有 ingest WriteFlow / 路由，遵守 G1（先 md）
- 前端：Life「训练」区新卡 + `WriteFlow`；文案明示「写入复盘 md，不是练练 App」
- 测试：临时目录 / 假 client；零真网；注册表与 422/门禁覆盖

**验收**

- [x] plan 不改盘；confirm 后 md 出现/更新训练块；回读校验通过
- [x] 与 `ks_*` 路由/注册表条目分离；UI 文案不混淆
- [x] `--enable-write` + key 门禁与现有写操作一致
- [x] 相关 Python / 前端测 + ruff；四处版本 **v1.93.0**；**不打 tag**

**明确不做**：自动代勾；只写库不写 md；改 `exercise_min` 评分口径；多步向导。

**按需 skill**：`daily-review-intake`。

### D2 — 今日训练日状态条 + CTA｜P0

**目标**：Today 一眼看到「练练是否 completed / md 是否已写 / 代勾是否可选」，并链到 D1 卡或既有 `ClickupHabitWrite`。

**依赖**：D1 已上板（否则「同步 md」CTA 空转）。

**实现要点**

- 只读聚合 API（或扩既有 today/life 查询）：复用 `keepstrong_completed_hint` 等，R1 单源
- UI：状态点 + 短标签 + ghost/primary CTA；**并列于** `ReviewSteps`，不并入四步
- 代勾 CTA 只打开既有确认流，不自动 apply

**验收**

- [ ] 三种状态展示与后端单源一致（单测或对拍）
- [ ] 无 completed 时不诱导代勾；无 md 时 CTA 指向 D1
- [ ] 不影响 `is_healthy` / 复盘四步语义

**明确不做**：超级向导；静默代勾；把训练步骤画进 ReviewSteps。

### D3 — 习惯鲜度进 summarize + Life CTA｜P0

**目标**：滞后天数进体检结构化卡；习惯页深链到已有 `habits-sync` 预览（仍二次确认）。

**实现要点**

- Doctor 前端 advisory 卡；Life 习惯 tab Highlights / CTA → `#` 定位到 sync 卡
- CTA **不是**自动 apply

**验收**

- [ ] summarize 与 diagnose 鲜度结论一致（对拍）
- [ ] 落后 / 空表有可见卡；点 CTA 只打开 plan 预览
- [ ] 不写 `habit_logs` 以外的表；不碰 R3

**明确不做**：Web 自动按区间 sync；把鲜度算进 `is_healthy`（保持建议性，除非既有口径已包含——以 doctor 现状为准，不扩大）。
