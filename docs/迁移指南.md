# DailyLumen 迁移指南（换机 / 重装）

> 目标：把本系统完整搬到另一台电脑继续跑。
> **核心结论**：代码与全部复盘原文都在 git 里，换机 ≈ `clone` + 2 条命令；
> 真正要手工处理的只有 **3 件事**（见第三节）。
> 本指南的结论来自实测（用仓库内 md 从零重建数据库，与真库逐字段比对 0 差异），
> 不是推测；复现方法见 `~/.workbuddy/skills/sqlite-safe-migration` 的
> 「重建可复现性自检」一节。

---

## 一、什么在 git、什么不在

### 已入库（`git clone` 即得）

| 内容 | 路径 |
| --- | --- |
| 全部代码 + 测试 + CI | `review_tool/`、`tests/`、`.github/workflows/ci.yml` |
| 打包 / lint 配置 | `pyproject.toml`、`requirements.txt`、`.gitattributes` |
| **全部复盘原文**（59 篇：每日 + 周总结 + 月总结） | `每日复盘/复盘/YYYY-MM/*.md` |
| 模板与目录说明 | `每日复盘模板.md`、`每日复盘/{收件箱,历史源复盘}/README.md` |
| 空库模板（schema v4） | `review_tool/reviews.example.db` |
| 文档 | `README.md`、`docs/设计说明.md`、`review_tool/README.md` |
| 项目级方法资产 | `.workbuddy/skills/doc-corpus-normalize/SKILL.md` |

### 不在 git（迁移盲区）

| 路径 | 内容 | 迁移动作 |
| --- | --- | --- |
| `review_tool/reviews.db` | **唯一数据源**（49 天 / 343 打卡 / schema v4 / 147 KB） | **可不带** —— 实测可从 git 里的 md 100% 重建（逐字段 0 差异）。想省一次 `ingest`、或留一份兜底快照，就手工拷一份 |
| `.workbuddy/memory/` | 项目长期约定 `MEMORY.md` + 每日执行日志 | **建议手工搬** —— 跨会话上下文，无法从代码重建（含口径拍板、工程约定、环境坑） |
| `.workbuddy/backup/` | 迁移前 DB 快照（`reviews.pre-*.db` 系列）+ 一次性脚本 + `archived/` | 可选，留档价值为主 |
| `.workbuddy/automations/` | 自动化执行摘要（memory.md） | 可重建；**不含调度定义**，调度需手工重建（见第三节） |
| `exports/` | 导出产物（CSV / JSON） | 可重建，不必搬 |
| `__pycache__/`、`.ruff_cache/` | 字节码与 lint 缓存 | 不搬，自动重生 |

> ⛔ 个人数据（`reviews.db`、`exports/`）**已被 `.gitignore` 排除**，不要试图提交。

## 二、环境依赖（新机只需要这些）

- **Python ≥ 3.10**（`pyproject.toml` 声明 `requires-python = ">=3.10"`；本机验证 3.13）
- **零第三方依赖** —— 纯标准库，`pip install` 一个包都不需要
- `git`（仓库为私有，从 GitHub 克隆需配好 SSH key）
- 可选：`ruff`（代码风格）、`pytest`（若偏好 pytest 而非 unittest）

---

## 三、新机落地步骤

```bash
# 1) 克隆（目录名随意 —— 代码里的路径全部由 __file__ 推导，不含绝对路径）
git clone git@github.com:deTian0/DailyLumen.git "每日复盘计划"
cd 每日复盘计划

# 2) 从 md 重建数据库（首次运行会自动按 schema.sql 建库）
python -m review_tool ingest

# 3) 体检：期望退出码 0、结论「数据健康」
python -m review_tool doctor

# 4) 全量测试（期望 288 项通过）
python -m unittest discover -s tests -t .

# 5) 冒烟：周报 / 熔断
python -m review_tool week --json
python -m review_tool fuse
```

**要手工处理的三件事**：

1. **搬项目记忆**（可选但强烈建议）：把源机 `.workbuddy/memory/` 整个拷到新机同位置。
   没有它系统照跑，但会丢掉口径拍板与工程约定等跨会话上下文。
2. **重建晨间收集自动化**（见下节）—— 自动化定义不在仓库里。
3. **`reviews.db` 带不带**：不带就走上面第 2 步重建；带的话直接放到
   `review_tool/reviews.db`，第 2 步仍建议跑一次并核对「0 处不一致」。

## 四、必须手工重建：晨间收集自动化

**自动化定义不在仓库里**（由 WorkBuddy 在本地注册），换机后需重建：

| 项 | 值 |
| --- | --- |
| 名称 | DailyLumen 晨间复盘收集（对话式） |
| 计划 | 每天 08:30 |
| 工作目录 | 必须是本仓库所在目录 |
| 状态 | 当前为 **PAUSED**（如已启用，按需恢复） |

⚠️ **该自动化的 prompt 里硬编码了绝对路径**（本机为
`D:\soft_data\WorkBuddy\每日复盘计划`，含收件箱的绝对路径）—— 新机路径不同**必须改**，
否则收件箱读不到、输出目录会落到错误位置。

对比：**代码本身不含任何硬编码绝对路径**（`config.py` 用 `os.path.dirname(__file__)`
逐级推导 `BASE_DIR` / `INPUT_DIR` / `DB_PATH`），所以只有自动化 prompt 依赖绝对路径。

## 五、换机后验证清单

- [ ] `python -m review_tool doctor` → 退出码 `0`，结论「数据健康」
- [ ] `doctor` 的「文件 ↔ 数据库对账」→ 未入库 `0` / 库中孤儿 `0`
- [ ] `python -m review_tool sync-docs --check` → `0 篇待同步`
- [ ] `python -m review_tool recompute-scores` → `0 处差异`
- [ ] `python -m review_tool fuse` → 信号与源机一致（有绝对熔断时退出码 1，属预期）
- [ ] `python -m unittest discover -s tests -t .` → 288 项通过
- [ ] `每日复盘/{收件箱,历史源复盘}/README.md`、`每日复盘模板.md` 在位
- [ ] `.workbuddy/memory/`（若搬了）在位，`MEMORY.md` 可读
