# DailyLumen 迁移指南（换机 / 重装）

> 目标：把本系统完整搬到另一台电脑继续跑。
> **核心结论**：代码、**全部复盘原文**、**项目口径与流程本身**（仓库自带的项目级 skill）
> 都在 git 里，换机 ≈ `clone` + 2 条命令；**真正要手工处理的只有 1 件事**（见第三节）。
> 本指南的结论来自实测（用仓库内 md 从零重建数据库，与真库逐字段比对 0 差异），
> 不是推测；复现方法见 `~/.workbuddy/skills/sqlite-safe-migration` 的
> 「重建可复现性自检」一节。

---

## 一、什么在 git、什么不在

### 已入库（`git clone` 即得）

| 内容 | 路径 |
| --- | --- |
| 全部代码 + 测试 + CI | `review_tool/`、`tests/`、`.github/workflows/ci.yml` |
| 打包 / lint 配置 | `pyproject.toml`、`requirements.txt`、`.gitattributes` |
| **全部复盘原文**（59 篇：每日 + 周总结 + 月总结） | `每日复盘/复盘/YYYY-MM/*.md` |
| 模板与目录说明 | `每日复盘模板.md`、`每日复盘/{收件箱,历史源复盘}/README.md` |
| 空库模板（schema v4） | `review_tool/reviews.example.db` |
| 文档 | `README.md`、`docs/设计说明.md`、`docs/迁移指南.md`、`review_tool/README.md` |
| **项目总纲**（范围 / 权威归属 / 评分与熔断口径 / 文档与库规约 / 工程约定 / 交付流程） | `.workbuddy/skills/dailylumen-conventions/SKILL.md` |
| **素材 → 复盘流程**（发截图 / 发文档 / 总结对话 → 成品复盘） | `.workbuddy/skills/daily-review-intake/SKILL.md` |
| 批量文档标准化 SOP | `.workbuddy/skills/doc-corpus-normalize/SKILL.md` |

> 项目级 skill 属**方法资产**，与代码同仓、随 tag 走版本（`tests/test_repo_layout.py` 守卫
> `.gitignore` 白名单规则）。所以**项目口径与日常流程都不需要任何手工搬运** ——
> 这是把长期约定从「本机记忆」搬进「仓库 skill」的直接收益。

### 不在 git（迁移决策：搬 / 重建 / 丢弃）

| 路径 | 内容 | 迁移动作 |
| --- | --- | --- |
| `review_tool/reviews.db` | **唯一数据源**（49 天 / 343 打卡 / schema v4 / 147 KB） | **手工搬运** —— 放到 `review_tool/reviews.db` 即可。搬完仍建议跑一次 `ingest` 核对「0 处不一致」。**不带也能跑**：实测可从 git 里的 md 100% 重建（逐字段 0 差异） |
| `.workbuddy/memory/` | 本机环境坑 `MEMORY.md` + 每日执行日志 | **不迁移** —— 项目口径已抽象为 git 内 skill；剩下的是本机环境坑与执行日志，属「这台机器」的属性，换机后不复现即作废 |
| `.workbuddy/backup/` | 迁移前 DB 快照（`reviews.pre-*.db` 系列）+ 一次性脚本 + `archived/` | **不搬** —— 留档价值为主；真出问题从源 md 重建更可靠 |
| `.workbuddy/automations/` | 自动化执行摘要 | 不搬 —— **本项目已无任何定时任务**（见第四节），无调度需要重建 |
| `exports/` | 导出产物（CSV / JSON，个人数据） | **不搬，重建** —— `python -m review_tool export` |
| `__pycache__/`、`.ruff_cache/` | 字节码与 lint 缓存 | **不搬，重建** —— 自动重生 / 重跑 ruff |

> ⛔ 个人数据（`reviews.db`、`exports/`）**已被 `.gitignore` 排除**，不要试图提交。

## 二、环境依赖（新机只需要这些）

- **Python ≥ 3.10**（`pyproject.toml` 声明 `requires-python = ">=3.10"`；本机验证 3.13）
- **零第三方依赖** —— 纯标准库，`pip install` 一个包都不需要
- `git`（仓库为私有，从 GitHub 克隆需配好 SSH key）
- 可选：`ruff`（代码风格）、`pytest`（若偏好 pytest 而非 unittest）

## 三、新机落地步骤

```bash
# 1) 克隆（目录名随意 —— 代码里的路径全部由 __file__ 推导，不含绝对路径）
git clone git@github.com:deTian0/DailyLumen.git "每日复盘计划"
cd 每日复盘计划

# 2) 从 md 重建数据库（首次运行会自动按 schema.sql 建库）
python -m review_tool ingest

# 3) 体检：期望退出码 0、结论「数据健康」
python -m review_tool doctor

# 4) 全量测试（期望 288 项通过）
python -m unittest discover -s tests -t .

# 5) 冒烟：周报 / 熔断
python -m review_tool week --json
python -m review_tool fuse
```

**唯一要手工处理的一件事**：

- **搬库**：把源机 `review_tool/reviews.db` 拷到新机同路径。搬完仍建议跑一次
  `python -m review_tool ingest` 并核对 doctor 的对账段「0 处不一致」；
  万一没搬或搬坏了，第 2 步的从零重建就是兜底（数据 100% 可重建，不会丢）。

> 除此之外**没有需要手工搬的东西**：项目口径与流程由 git 内 skill 承载；
> `.workbuddy/memory/`、`backup/` 不迁移；`exports/`、缓存全部重建。

## 四、无需重建任何定时任务（v1.4.6 起）

原「**DailyLumen 晨间复盘收集（对话式）**」自动化（每天 08:30）**已删除**。
现在的工作方式改为**按需**：

| 项 | 现在怎么做 |
| --- | --- |
| 素材怎么进来 | **用户手动投递** —— 在对话里直接发截图 / 发文档 / 发文字简报；`每日复盘/收件箱/` 仍可作手动投放点，但不再有自动化去扫 |
| 谁来处理 | 按需加载的项目级 skill **`daily-review-intake`**（自带日期归属、字段顺序、评价/建议规格、格式规范） |
| 换机要做什么 | **什么都不用做** —— 流程在 git 里（skill），不在本机调度器里 |

顺带解决的历史遗留：原自动化的 prompt 里「星期用单字」与项目 v1.3.3 定版的
「`星期` 一律写全称」相冲突，且硬编码了绝对路径 `D:\soft_data\WorkBuddy\每日复盘计划`。
转成 skill 后写法统一到**全称**，且**不含任何绝对路径**（路径由 `config.py` 的
`__file__` 推导）。

      `daily-review-intake` / `doc-corpus-normalize`）—— 口径与流程的可迁移载体
