# 每日复盘素材 → 成品复盘（按需触发）

> v1.4.6 起**不再有定时任务**：素材由用户**手动投递**（直接在对话里发截图 / 发文档，
> 或说「总结一下我们刚才聊的」），由本 SOP 生成当日复盘。原先的「晨间收集自动化」已删除，
> 本 skill 就是它的替代品 —— 但机制从 **always-on 调度** 换成 **按需加载**。
> 项目口径（评分 / 熔断 / 权威归属 / 规约）见 skill `dailylumen-conventions`，这里只讲流程。

## 触发与开场

用户发来截图 / 文档 / 文字简报，或直接说「把今天复盘弄一下」时：

1. 先确认**归属日期**（见 §2），不确定就问一句。
2. 读取素材并抽取客观数据。
3. 按 §3 生成 / 更新复盘文件，按 §4 出「AI 评价与建议」。
4. 按 §5 收尾回复。

**开场白（可直接用）**：请把今日简报文字 / 相关截图直接发我；我抽取客观数据、
回填当日复盘并生成带「AI 评价与建议」的成品，输出到 `每日复盘/复盘/YYYY-MM/`。

## 1. 素材来源（本项目不再有收件箱依赖）

- **对话直发**（主路径）：截图（睡眠 / 运动 / 饮食 / 屏幕使用时间…）+ 文字简报
- **对话里发文档**：md / txt / pdf
- `每日复盘/收件箱/`：仍可用作**手动**投放点（素材多、跨设备时方便），
  但**不再有自动化去扫**，需要用户明确说「去收件箱读」才读
- 约束：**不删除、不改动**用户的原始素材；收件箱文件处理完保留

## 2. 日期归属（最容易出错的环节）

按「**晨间回顾昨日**」惯例，数据归入其**真正代表的那一天**：

| 素材 | 归属 |
| --- | --- |
| 睡眠截图 | 归**入睡那一夜**（早上看到的睡眠报告 = 昨晚） |
| 饮食 / 屏幕使用时间截图 | 按图上标注的日期 |
| 运动截图 | 按图上日期；若为「今天刚做完」，归属当天 |
| 文字简报 | 按用户叙述的日期；跨天就分开处理 |

同一批素材可能跨两天 → **拆成两份复盘**，别硬塞进一天。

## 3. 生成 / 更新复盘文件

1. 在 `每日复盘/复盘/{YYYY-MM}/YYYY-MM-DD.md` 生成或更新（目录路径由 `config.py`
   的 `__file__` 推导，**不要写绝对路径**；新的一天用 `python -m review_tool new-day` 起模板）。
2. 把客观数据回填进文末 **附录 · 系统数据** 的 ```` ```data ```` 块，字段顺序固定：
   日期 / 星期 / 训练日 / 睡眠时长_h / 睡眠质量 / 入睡时间 / 运动时长_min / 饮食热量_kcal /
   碳水_g / 脂肪_g / 蛋白质_g / 三餐情况 / 早餐按时 / 手机屏幕_h / 深度工作_h / 学习投入_h /
   生活投入_h / 一句话总结。
   - 缺数据**留空**，不要写「⚠️ 缺数据」之类的占位符
   - **不写「补剂完成」**（补剂 / 护肤由「一、日常打卡」勾选提取到 `personal_tracks`）
   - 不要塞图片注解、不要写截图路径
3. **用户原文照录**：一~五章节的叙述**原样保留、不改写**（AI 只补数据与评价）。
4. 入库算分：`python -m review_tool ingest`
5. 回填六段：`python -m review_tool sync-docs`（**分数由库渲染，别在 md 里手改分数**）。

## 4. 生成「七、AI 评价与建议」

先取确定性上下文，再据此撰写：

```bash
python -m review_tool ai-context YYYY-MM-DD     # 当日事实 + 近 7 日均值 + 规则命中的关注点
```

| 部分 | 要求 |
| --- | --- |
| **评价** | 2–3 条，覆盖「做得好」与「需留意」，**必须引用上下文里的真实数字**（如「睡眠 7.17h、质量 89」） |
| **建议** | 2–4 条可执行动作，带**时间锚点或目标值**（如「22:30 手机放客厅，目标 23:30 前熄灯」「碳水补到 220g」） |

⛔ **不得编造上下文未列出的数据**；上下文没覆盖的日期或指标不要臆断。
排版：`**评价**` 用无序列表；`**建议**` 用 `1. **加粗引领**：…` 编号列表；**都不用表格**。

## 5. 格式规范（强制）

- 标题：`# 每日复盘 · YYYY-MM-DD（星期X）` —— **星期一律写全称**（星期一…星期日）
  （这是 v1.3.3 定版的项目规约；历史上用单字的都已被标准化，别再写回单字）
- 章节顺序固定：一、日常打卡 → 二、今日三件事 → 三、一个改进点 → 四、明日 Top 3 →
  五、时间投入 → 六、四维评分 → 七、AI 评价与建议 → 附录 · 系统数据
- 一、日常打卡：`**晨间（起床后）**` + `- [x] 补剂…` **嵌套勾选列表**，不用表格
- 五、时间投入：三行 `- 深度工作（h）：N`，各带 `← 对应数据块` 尾注
- 六、四维评分：表格 `| 维度 | 分数 | 状态 | 待补字段 |`
- 缺「七、AI 评价与建议」= 当日确实没有 AI 建议（内容事实），**不补空占位**
- 完整模板见仓库根目录 `每日复盘模板.md`，不一致时以它为准

## 6. 收尾回复

简短告知：**处理了哪一天**、**回填了哪些数据/素材**、**生成了哪个文件**（完整路径）、
**给了几条评价与建议**。然后按项目 5 步协议写执行摘要（见 `dailylumen-conventions` §7）。

## 7. 与项目规约的衔接（别踩）

- 改了评分规则 / 想调口径 → 走 CLI（`recompute-scores --apply` + `sync-docs`），
  不要为了「看起来对」去手改 md 里的分数（下一次 CLI 跑动就归位）
- 训练日**没填 = 没练**（若当天确实做了徒手训练但只在「二、今日三件事」写了动作，
  系统会按 `config.BODYWEIGHT_MOVES` 自动折算运动时长；想自己控制就在数据块填 `运动时长_min`）
- 补了历史某天的数据 → 重跑 `ingest`，再 `doctor` 看「打卡对账 / 分数一致性」是否干净
